# موقع WhyQaraan بأقل موارد تشغيل

## القرار

Astro بتوليد صفحات ثابتة، ومقالات عربية في Markdown ومجموعات محتوى تتحقق من حقول المقالات وقت البناء. تؤكد [وثائق Astro](https://docs.astro.build/en/guides/on-demand-rendering/) أن الإعداد الافتراضي يولد الصفحات وقت البناء. وتناسب [مجموعات المحتوى وقت البناء](https://docs.astro.build/en/guides/content-collections/) المقالات والبيانات التي تتغير عند التحرير.

تعمل أدوات Python محليا أو في مهمة البناء. تنتج JSON ثابتًا ونتائج يمكن الرجوع إليها. يستقبل القارئ HTML وCSS والصور اللازمة؛ لا نحتاج جلسات مستخدمين أو اتصالًا بقاعدة بيانات لقراءة المقالات. لا نحمل فهرس القرآن الكامل لكل زيارة؛ يمكن تقسيم فهارس البحث عند الحاجة.

## مكونات المرحلة التالية

- لغة `ar` واتجاه `rtl`، وخط عربي واضح، وصفحات مريحة للقراءة على الهاتف.
- فهرس مقالات حسب الألفاظ والأسماء والبلاغة والأعداد والعلوم والأسرة، وصفحة لكل مقال.
- في المقال: السؤال، النص والسياق، التحليل، النتيجة وحدودها، المصادر، وطريقة إعادة الحساب إن وجدت.
- رابط بيانات الدليل وتاريخ المراجعة، مع توضيح هل المحتوى ملاحظة أو تفسير أو فرضية.
- نشر المقالات التي خرجت من حالة المسودة فقط. لا تصدير واجهة ترخص في تغيير النص المصدر.
- بحث في المتصفح عند الحاجة إلى ذلك، مع تحميل كسول للفهارس؛ لا حاجة إليه في أول صفحة مقالات.
- استضافة ملفات ثابتة على CDN أو خادم ملفات عادي. اختيار مزود ودومين ونشر فعلي في مرحلة لاحقة.

## ميزانية مبدئية

هدف التصميم: صفر JavaScript مخصص في صفحات المقالات الأساسية ما لم تتطلب تجربة تفاعلية، وصفر طلبات إلى خادم تطبيق عند القراءة. كلفة البناء والتخزين ونقل البيانات لا تختفي. لا نحمل صورا كبيرة أو كامل مجموعة البيانات في كل صفحة. هذه أهداف للمرحلة التالية وليست قياسات لموقع مبني الآن.

## صيغة المقال

الملفات في `content/articles/` تستخدم frontmatter يحوي `title`, `description`, `date`, `draft`, `evidence_ids`, `category`. يبقى المتن عربيا، وتصل أسماء الأدلة المقال بسجل قابل للفحص. لا تلزم MDX أو React في البداية.
