# WhyQaraan website implementation plan

> **For agentic workers:** Use the relevant execution skill; the user has explicitly delegated execution and requested continuous progress. Keep task ownership disjoint and preserve all research decisions in the repository.

**Goal:** Build a verified Arabic static article website and retain the complete editorial research backlog.

**Architecture:** Astro consumes existing Markdown, verified Python reports, and an editorial JSON register at build time. Research remains in Arabic with immutable Quran source files. Default builds exclude drafts; review previews explicitly include them.

**Tech Stack:** Astro static output, CSS, TypeScript for build-time validation, Python standard-library research tooling.

**Spec:** docs/superpowers/specs/2026-11-02-website.md

## Global Constraints

- Arabic RTL, no runtime server/database, no unnecessary browser JS.
- Preserve data/source/ byte-for-byte.
- Only whole-Quran readers own Quran research; retain honest reading ledgers.
- No unreviewed draft in the default build; preview drafts carry noindex and a visible label.
- No claim of a new scientific discovery without evidence.

## Review Focus

1. A draft accidentally reachable by its URL after an otherwise empty index: test built paths.
2. A published article whose evidence reference or review record is missing: fail build-time validation.
3. Relative repository links becoming broken browser links: inspect every local link in built HTML.
4. Arabic text/tables overflowing at 390 px: browser check RTL, heading and table widths.
5. Numbers presented without spelling/basmala/unit definitions: editorial review and page checks.
